## 알게 된 사실 / 막힌 지점
1. **파일 간 스코프는 통한다** — 별도 `text/babel` 파일 사이에 `function`·`const`·
   `class` 가 서로 보이고 순서도 보장된다. 먼저 실증했다. 아니었으면 117개 선언을
   전부 `window` 에 올려야 했다.
2. **`.jsx` 는 Cloudflare 가 압축하지 않는다.** `text/jsx` 가 압축 대상 MIME 이 아니다.
   나눈 직후 전송량이 124KB → 649KB 로 뛰어서 알았다. `.js` 로 바꾸니 brotli 가 걸렸다.
3. **Workers Assets 는 자산이 있으면 Worker 를 아예 거치지 않는다.** worker 에서
   content-type 을 고치는 코드를 썼는데 실행조차 안 됐다(`.jsx` 응답에 보안 헤더가
   안 붙는 것으로 확인). 되돌렸다 — 도달하지 않는 코드는 거짓 안심을 준다.
4. **조각별 압축은 통짜보다 41% 비효율.** 통짜 brotli q11 = 99.6KB, 조각 넷 = 141KB.
   압축 사전이 파일마다 리셋되기 때문이다. 이 대가는 숨기지 않고 적었다.
5. **검사기 셋이 확장자로 대상을 골랐다** — `.js` 로 바꾸자 동시에 눈을 감았고,
   인벤토리는 탭을 50 → 0 으로 셌다. 오류 없이 숫자만 조용히 0이 됐다.

## 검증
- **무손실**: 네 파일을 이어 붙여 원본과 비교 — **511,180자 완전 일치**.
- **스코프·순서**: 로컬 `wrangler dev` 에서 **117개 최상위 선언이 전부 정의되는지**
  브라우저에서 직접 셌다 — 누락 0. 순서나 스코프가 어긋나면 여기서 잡힌다.
- **라이브**: 배포 후 48개 표본 + **탭 50개**(`buildTabs()` 실행) + 4파일 로드 +
  워치독 무장 재확인.
- **압축**: `content-encoding: br` 확인. 파일별 압축률 24~27%.
- **성능**: 캐시 끄고 3~5회 측정, 중앙값 사용.
- 매 배포마다 렌더 스모크 통과(v01.101.11 에서 만든 것이 이번에 실제로 쓰였다).

## 되돌아본 것
- worker 에서 content-type 을 고치려 한 시도 → **닿지 않아 되돌림**.
- `.jsx` 25개 전부 전환은 **하지 않았다** — 참조가 여러 파일에 흩어져 범위가 커진다.
  공개 사이트 501KB 는 별도 판단으로 남긴다(운영자에게 보고함).

## 설계 근거 (왜 이렇게 하나)
- **세 겹이 겹치는 게 아니라 각자 다른 실패를 잡는다**:
  워치독 = React/Babel 이 **아예 못 뜬** 경우 (에러 경계도 못 잡는다)
  에러 경계 = **렌더 중** 예외
  전역 핸들러 = **이벤트 핸들러/비동기** 예외 (에러 경계가 못 잡는다)
- React 18 UMD 라 에러 경계는 **클래스 컴포넌트**만 가능 (`getDerivedStateFromError`).
- 보고가 렌더를 다시 깨는 **무한 루프**를 막는다 — 세션당 1회.
- **관리자 화면이라 보고 payload 에서 Bearer 토큰을 마스킹**한다. 공개 `/api/errors` 로 나간다.
- 스모크는 **시스템 Chrome** 을 쓴다 (npm 설치 0). Chrome 이 없으면 **"못 돌렸다"**고
  말한다 — 통과로 세지 않는다.

## 검증 (전부 일부러 깨뜨려 확인)
- **재귀검사**: v01.101.10 의 **실제 사고 코드를 되돌려** 잡는 것을 확인(`:577 authHeaders`).
  같은 코드를 **구문검사는 여전히 통과**시킨다 — 두 검사가 서로 다른 것을 본다는 증명.
- **구문검사(인라인)**: `admin.html` 507줄에 깨진 토큰을 넣어 종료코드 1 확인.
  보고된 줄번호가 **실제 파일 줄번호와 일치**(패딩 검증).
- **에러 경계**: 배포본에서 클래스를 **그대로 추출**해 하네스로 — 안내 표시 ·
  `fineAlive: true`(옆 경계 자식 생존) · `scope` 보존 · payload·화면 모두 토큰 없음.
- **워치독**: React 를 아예 안 실은 페이지에서 안내 · 재시도 버튼 · 보고 확인
  (`has_react: false` 진단 포함).
- **스모크**: `example.com` 에 겨눠 백지를 잡는 것 확인(종료코드 1). 정상일 때 0.
  못 읽었을 때 2(실패와 구분).
- **운영 격리**: 하네스에서 `sendBeacon` 을 가로채 **운영 `/api/errors` 를 건드리지 않았다.**

## 되돌아본 것 (첫 판을 버린 곳 둘)
1. 스모크 첫 판(`--dump-dom --virtual-time-budget`)이 **멀쩡한 홈을 죽었다고** 보고했다.
   가상 시계가 워치독의 `setTimeout(9000)` 을 즉시 터뜨렸다. → CDP 실제 시간 폴링.
2. 재귀검사 첫 판이 `setDeep` 을 오탐. → **문턱을 낮추지 않고 규칙을 하나 더**
   (조건부 탈출구가 있으면 제외).
3. 스모크가 10분 17초 걸렸다 — Chrome 을 죽여도 `stderr`·소켓 핸들이 이벤트 루프를
   붙잡았다. 명시적으로 끊어 **7초**.

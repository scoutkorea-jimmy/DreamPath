# HANDOFF · 등록금 표기를 "미공개 · 예약 단계"로

- **시작**: 2026-08-23 (KST)
- **지시 원문**: "프로그램 등록금은 아직 미공개거나 예약 단계라고해줘. 딱 그정도로"
- **상태**: 완료 (2026-08-23) · v01.098.01

## 해석
임시값 `500` 을 실제 금액으로 채우는 게 아니라, **금액을 감추고 상태로 표시**한다.
"딱 그정도로" = 장황한 안내 만들지 말고 한 줄 상태 표기까지만.

## 진행
- [x] 등록금 사용처 전수 → 값 2곳(KV·기본값) · 표시 3곳 · 서버 계산 1곳 · 관리자 1곳
- [x] 값 0(미공개)으로 통일 + 표시를 상태 문구로 · v01.098.01 배포

## 적용
| 자리 | 처리 |
|---|---|
| KV `programs[].tuition` ×5 | `500` → **`0`(미공개)** |
| `content-store.js` 기본값 5개 | `500` → `0` + 주석에 "0 = 미공개(예약 단계)" 명시 |
| 마이페이지 결제 화면 | 금액 자리에 **"미공개 · 예약 단계"** (EN: Not published yet · reserved) |
| 결제 실패 메시지 | "등록금이 설정되지 않았습니다 · 관리자 문의" → **"등록금은 아직 미공개입니다(예약 단계). 확정되면 안내드리겠습니다."** |
| 프로그램 상세 Pricing 섹션 | 등록금 미공개면 **금액 비교 섹션 자체를 렌더하지 않고** 한 줄 상태 안내로 대체 |
| 관리자 등록금 입력 | 힌트 추가 — "비워 두거나 0이면 '미공개 · 예약 단계'로 표시되고 결제가 차단됩니다" |

## 왜 Pricing 섹션까지 건드렸나
상세 페이지의 비용 섹션은 `$720` · `12 credits × $60` · `$14,258–$29,258 절감` · `97% less` 같은
**구체 금액 주장으로 가득하다.** 등록금을 "미공개"라고 해놓고 그 옆에서 이 숫자들을 말하면
그 자체가 모순이다. 지우지 않고 **`tuitionPublished` 조건으로 렌더만 막았다** — 금액이
확정돼 값이 들어가면 자동으로 돌아온다.

## 서버 쪽
`computeTuition()` 이 0 을 돌려주면 `POST /pay` 는 이미 `409 tuition_not_set` 으로 막는다.
즉 **금액이 미공개인 동안 결제는 구조적으로 불가능**하다(현재는 그 앞의 접수 차단 503 이 먼저 걸린다).

## 검증
- KV 5개 프로그램 `tuition: 0` 확인, 관리자 콘솔 정상(4xx 0 · 예외 0), 공개 사이트 4xx 0 · 예외 0.
- 결제 엔드포인트 차단 확인.

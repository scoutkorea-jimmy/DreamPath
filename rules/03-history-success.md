내용이 통째로 사라졌다. 또 '새 메일'을 눌러 작성 화면에 들어간 뒤에도
접힌 제목(`admin-fold`)을 한 번 더 눌러야 입력칸이 나왔다.

**고친 것** (`admin.html` · `MailboxTab`)
- `<details className="card admin-fold" open>` — 작성 화면에서는 항상 펼침.
- `saveDraftNow()` + 60초 인터벌 · `beforeunload` · 언마운트 · '닫기' 버튼.
- 키는 계정별: `dp_mail_draft_v1:<lockedAccount|all>`.

**함정 둘**
1. 상태를 `useEffect` 의존성에 넣으면 **타이핑마다 인터벌이 리셋**되어
   60초가 영영 오지 않는다 → 최신 값은 `composeRef` 로만 읽는다.
2. RichEditor 는 빈 상태에서도 `<p></p>` 를 남긴다 → 빈 판정은 태그를
   벗겨서(`draftIsEmpty`). 안 그러면 빈 초안이 계속 저장된다.

**의도적으로 안 한 것**: D1 초안 테이블. 초안은 이 브라우저의 작업 상태이고
마이그레이션 없이 즉시 효과가 있다. 첨부(≤50MB)는 localStorage 한도(≈5MB)를
넘겨 제외 — 서버 초안이 필요해지면 그때 승격.

**검증**: preflight 통과 · `@babel/standalone` 로 admin.html 3개 스크립트 블록
파싱 확인 · 배포 후 라이브 `version.js` = 01.100.00 · 라이브 admin.html 에
`admin-fold" open` 존재 확인.

## 2026-08-25 · 에디터 본문 높이 조절 (v01.101.00)

**요청**: "메일 작성 시 바디영역을 늘리고 줄일수 있게"

**한 것** (`RichEditor.jsx` · `site.css` · `admin.html`)
- `resizable` / `storageKey` prop. 손잡이 `.rt-resize` + 높이 기억.
- 드래그는 `pointerdown/move/up` — 마우스·터치·펜을 한 경로로.
- 저장은 `pointerup` 1회. move 마다 쓰면 드래그가 무거워진다.

**고른 이유** (`resize: vertical` 을 안 쓴 이유)
CSS 한 줄이면 될 것 같지만 셋이 안 된다 — ① 높이가 기억되지 않는다
② TipTap 컨테이너에서 브라우저 기본 손잡이가 잘 보이지 않는다
③ 키보드로 조절할 수단이 없다. 그래서 prop 방식.

**같이 손봐야 했던 것**: `.rt-content .ProseMirror { min-height:140px }` 가
작은 높이와 싸운다 → `.is-resizable` 일 때 `min-height:100%` 로 바꿨다.
안 그러면 120px 로 줄여도 내부가 140px 라 늘 스크롤이 생긴다.

**기본값을 false 로 둔 이유**: 같은 컴포넌트를 페이지 편집기·프로그램 상세도
쓴다. 전역으로 켜면 요청하지 않은 화면 셋이 같이 바뀐다.

**검증**: preflight 통과 · `@babel/standalone` 파싱 확인 · 배포 후 라이브
`version.js` = 01.101.00 · `RichEditor.jsx` 의 `rt-resize` 3회 ·
`site.css` 의 `rt-resize-grip` 확인.

## 2026-08-25 · 안정성 자체 감사에서 결함 3건 (v01.101.01)

운영자 질문 "시스템 안정성을 해치지 않니?" 를 받고 앞 두 라운드를 다시 훑었다.
안심시키는 대신 실제로 감사했더니 셋이 나왔다.

**가장 나빴던 것**: `RichEditor.jsx` 가 **공개 사이트에도 실린다**는 것을
작업 중에 확인하지 않았다 (`index.html:68` · `Pages.jsx` 뉴스 편집기).
관리자 기능이라고 생각하고 고쳤는데 블라스트 반경이 공개 화면까지였다.
→ 이 파일을 고칠 때는 공개 사이트 확인이 필수.

**결함 3**
1. 드래그 중 언마운트 → `pointerup` 미도달 → window 리스너 잔존 +
   `body{user-select:none}` 눌러붙음(새로고침해야 풀림).
   `pointerup` 만 믿으면 안 된다 — **오지 않는 경로가 실재한다.**
2. `userSelect` 복원을 `''` 로 했다. 그건 복원이 아니라 **삭제**다 —
   남이 걸어둔 값을 지운다. 시작 시점 값을 들고 있어야 한다.
3. 임시저장 `catch {}` — 실패해도 화면은 옛 시각으로 "임시저장됨" 이라
   거짓말했다. 그걸 믿고 탭을 닫으면 내용이 사라진다.
   기억 `failures/조용히-사라지는-것들.md` 의 재발이다.

**같이 확인한 것 (문제 없었음)**: worker.js · migrations · wrangler.jsonc
무변경(git diff 공백) · `MailboxTab` 은 `TabComp` 하나로 렌더되어 동시
마운트 없음(초안 키 충돌 없음) · site.css 는 추가만, 기존 셀렉터 무수정 ·
`--state-warning-bg` 토큰 라이트/다크 양쪽 존재.

**교훈**: 새 기능마다 "이 파일을 누가 또 로드하는가"를 먼저 세어라.
그리고 **빈 `catch` 는 안정성이 아니라 안정성의 반대다** — 오류를 감추면
사용자가 잘못된 판단을 한다.

## 2026-08-27 · 메일 읽기 창이 한 글자씩 세로로 접혔다 (v01.101.02)

**증상** 관리자 → 메일함에서 메일을 열면 제목이 한 글자씩 18줄로 접히고,
본문 첫 줄에 SES message-id 가 그대로 보였다.

**어떻게 잡았나** `admin.html` 의 `<style>` 과 `sanitizeMailHtml` 을 **실물에서
추출**해 재현 페이지를 만들고 Playwright 로 폭을 쟀다. 손으로 옮겨 적은 사본으로
먼저 시도했다가 재현에 실패했다 — 사이드바를 빼먹어 pane 이 넓었기 때문이다.
운영자 스크린샷에서 카드 폭을 역산(551px)해 하네스를 989px 로 고정하자 그때서야
수치가 맞아떨어졌다(카드 553 · 제목 칼럼 17px · 제목 18줄).

**원인 셋**
1. 읽기 창 툴바가 `flexShrink:0`. 고유 폭 467px 를 양보하지 않아 제목 칼럼이
   17px 로 굶었다. `minWidth:0` 은 붕괴를 **허용**할 뿐 막지 않는다.
2. `sanitizeMailHtml` 이 `style` 을 지우면서 `display:none` 프리헤더가 드러났다.
3. `.mail-body table` 에 `width` 가 없어 살균으로 `width=` 를 잃은 중첩 테이블이
   셀을 min-content 까지 압축할 수 있었다.

**배운 것**
- **폭 경쟁은 폭으로 풀지 말고 없애라.** `flex-wrap` 이나 basis 조정은 특정
  폭에서만 성립한다. 세로 2단은 어떤 폭에서도 성립한다.
- **UI 붕괴 버그는 운영자 화면 폭을 재현해야 보인다.** 개발자 화면이 넓으면
  멀쩡하다. 스크린샷에서 픽셀을 역산할 수 있다 (Retina 는 2배).
- **재현 하네스는 소스에서 추출해라.** 손으로 옮기면 옮기는 순간 낡는다.

## 2026-08-27 · 발신자가 반송 주소로 저장되고 있었다 (v01.101.03)

메일함 발신자가 `010c01a…@ap-northeast-2.amazonses.com`. 운영자가 "이게 정상이야?"
라고 물어 드러났다.

**원인** `message.from` 은 Cloudflare 가 주는 **envelope sender**(MAIL FROM /
Return-Path)다. 대량 발송 서비스는 여기에 VERP 반송 주소를 넣는다. 사람이 읽고
회신할 주소는 `From:` 헤더에 있다.

**표시 문제가 아니었다** `startReply()` 가 `from_addr` 를 답장 수신자로 잡는다.
눌렀다면 반송 처리기로 나갔다.

**배운 것**
- **"두 개가 있는데 대개 같은 값"인 필드를 조심해라.** envelope From 과 헤더 From,
  `to_addr` 과 Delivered-To 가 그렇다. 평소엔 같아서 틀린 쪽을 읽어도 몇 달간
  아무 일도 없다가, 특정 발신자 하나가 들어오는 순간 드러난다.
- **보이는 값이 이상하면 그 값을 쓰는 곳을 전부 세어라.** 표시만 고치고 끝냈으면
  답장은 계속 틀렸을 것이다.
- **`parseEmailAddress()` 는 꺾쇠가 없으면 입력 전체를 반환한다** — `From: Mailer
  Daemon` 에서 이름을 주소로 저장했을 것이다. 못 찾으면 **빈 값을 돌려주는**
  `firstEmailAddress()` 로 갈랐다. 폴백은 빈 값에서만 걸려야 한다.
- **원본을 안 남기면 백필도 없다.** `raw_size` 만 저장해 기존 15통은 못 고친다.
